# 2026-11-23

## Done

- 新增 `./pipeline` 入口：有界并发阶段执行器，含阶段/条目状态机、原子 JSON 快照与断点续跑。
  - `run` 进程内处理异步任务；`worker: { entry, export }` 用 `node:worker_threads` 跑 CPU 密集任务，并发数即线程数。
  - 失败按条目聚合，不中断整批；`failFast` 可选提前停止派发。
  - 取消通过 `AbortSignal` 传播，worker 线程会被终止。
- `createFilePipelineStore` 原子写 + 刷新窗口合并；`createMemoryPipelineStore` 供测试与示例。
- 契约同步：`package.json#exports`、`tests/exports.test.ts`、`docs/reference/api.md`、`docs/guide/pipeline.md`、架构入口矩阵、CI 产物断言。
- 覆盖率棘轮上调到 73 / 65 / 73 / 73。
- 环境分层改为「一环境一文件」：`loadEnvFile` 先读 `env.file`（默认 `.env`），再按本地开关叠加 `<file>.dev` / `<file>.prod`；缺文件跳过，后者覆盖前者，进程环境始终优先。
- 删除 `env.onlineSuffix`、`readOnlineTarget`、`applyOnlineEnv` 与 `<KEY>_ONLINE` 展开；`ensureEnvFile` 只写 `<file>.dev`（无则写基础文件），永不改 `<file>.prod`。
- `ensureEnvFile` / `ensureDevServices` 的 `preserveRemote` 一并移除。

## Decisions

- 不重新发明 dotenv：用 `.env` + `.env.dev` / `.env.prod` 这种熟知形式表达环境差异，避免 `*_ONLINE` 这类抽象。
- 远端值来自 `<file>.prod` 或进程环境变量，键名不变，打包到 prod 时无需重写 key。
- 本地地址只进 `.dev`，从结构上杜绝 localhost 泄进部署文件。
- 新能力作为独立叶子模块：`pipeline` 不依赖 `cli` / `local`，由宿主自己接进 `CommandSpec`。
- Worker 入口是内部构建产物（`dist/pipeline/worker-entry.js`），不作为公开导出；`resolveWorkerEntry` 从模块位置解析，不依赖 `cwd`。
- 持久化写失败视为运行失败，而不是静默降级。
